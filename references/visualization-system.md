# 行业研究可视化系统

## 可视化路由

研究每个关键判断时先识别证据形态，再选择表现方式。图形必须帮助读者理解趋势、结构、差异、流程或物理形态，不以装饰为目的。

| 证据形态 | 首选方式 | 典型内容 |
| --- | --- | --- |
| 精确市场数据 | 交付工具原生图表 | 市场规模、增速、份额、价格、渗透率、融资和时间序列 |
| 技术与硬件结构 | 可编辑示意图或经校验的生成式图片 | 技术栈、芯片与设备结构、信号流、数据流、部署架构 |
| 产业与商业关系 | 流程图、关系图、矩阵或价值链图 | 产业链、商业闭环、客户采购、竞争定位、生态协作 |
| 真实产品与设备 | 官方图片、产品手册、论文或专利插图 | 产品外观、内部结构、设备部署和应用场景 |
| 外部研究图 | 提取口径并重绘，必要时作为证据截图 | 咨询公司分类、市场口径、路线划分和行业结构 |

## 数据图表

- 使用可审计的底层数据生成原生图表，图表范围直接引用数据单元格或公式驱动的辅助区域。
- 在标题、坐标轴或图下注明指标、时间、单位、地区和口径。
- 在相邻区域或来源台账保留原始网址、发布日期、来源角色和限制条件。
- 区分历史数据、机构预测、公司口径和研究推演。未知值保持空白，不补造零值。
- 一个图只表达一个主要判断。类别比较使用排序条形图，时间趋势使用折线图，少量份额使用堆叠条形图或紧凑份额图，复杂路线比较使用矩阵。
- 图片生成模型不得绘制精确市场图表、坐标轴、份额或参数。

## 技术与硬件图

- 核心技术行业至少评估技术栈、工作流程、硬件结构和替代路线四类图形，其中选择最能改变投资判断的两至四项进入成品。
- 优先使用官方架构图、论文、专利、产品手册和实物图片确认事实关系。需要统一视觉或缺少素材时再使用图片生成模型。
- 生成式图片只表达结构、层级、物理形态和场景。复杂中文标签、精确参数和性能数据在 Excel 中叠加；聊天交付使用文字、Markdown 表格或可追溯图表。
- 交付前核对术语、层级、连接方向、组件数量、输入输出、硬件依赖和安全边界。无法核实的结构标记为概念示意。
- 技术图附近保留文字解释，说明路线、工程瓶颈、成本与性能取舍、产品适配和投资意义。

## 外部报告图

- 搜索咨询公司、券商、研究机构、论文和行业报告时，同步记录图名、页码、发布日期、指标口径和原始链接。
- 外部图优先用于发现分类方法、数据口径和视觉表达。最终成品依据原始数据重绘并统一样式。
- 原始截图仅在证据保真价值高于可编辑性时使用，例如展示官方架构、专利结构或机构原始预测。截图必须清晰、完整并保留出处。
- 不截取缺少标题、图例、单位、时间或来源的局部图形，不把机构预测改写为确定事实。

## 图片生成模型

- 使用图片模型绘制产品形态、部署场景、技术概念和物理关系，画面采用低饱和研究报告风格，避免营销海报质感。
- 提示词明确画面用途、结构关系、视角、色盘、留白区域和禁止出现的虚构文字或数字。
- 复杂图优先生成无文字底图，再在交付工具中叠加可编辑标签、箭头和数据。
- 每张生成式图片必须经过视觉检查和事实检查。发现组件关系错误、文字乱码、数量失真或技术暗示超出证据时重新生成或删除。

## 交付门禁

- 摘要页至少包含一项能够强化核心判断的图形，数据不足时使用有证据边界的定性关系图。
- 核心市场数据、技术路线、竞争格局和商业化路径不得全部依靠文字或宽表表达。
- 图表、图片和正文形成对应关系，读者能够从图中得到明确判断，并在附近找到解释和来源。
- Excel中的关键图表保持原生可编辑；嵌入图片在正常缩放下清晰，避免因跨越过多列导致整体缩放后难以阅读。
- `delivery-check.json` 的每项可视化固定记录 `id`、`sheet`、`type`、`evidence_ids`、`data_range`、`source_urls`、`qa_status` 和 `limitations`。图表来源网址必须覆盖其证据编号对应的来源。
