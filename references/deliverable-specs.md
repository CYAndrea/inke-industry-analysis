# 交付规范

## 通用结构

使用“结论在前、证据在后”的顺序：摘要与核心观点、概念与技术、产业链与竞争、市场或标的比较、行业与标的观点、跟踪清单与来源。

## 聊天

用户明确选择聊天后，在对话中交付。开头回答用户的决策问题，再说明关键依据、风险、反证条件和待核验项。关键数字与结论使用直达链接；公司自述、媒体转述和模型判断分开表达。只有横向比较明显提高理解效率时使用 Markdown 表格。聊天路径不创建 `delivery-check.json` 或 `research-record.json`。

## Excel

工作表由已通过校验的 `narrative-draft.json` 与 `completion-audit.json` 共同生成。叙事稿形成摘要和连续正文，完成审计形成当前 `output_profile` 的全部核心模块页。复制 `assets/excel-build-config.json`，填写叙事稿、证据台账、模块完成审计、输出位置和工作区依赖路径后调用 `scripts/build_research_excel.mjs --config <配置文件>`。样式文件默认由生成器从 Skill 根目录加载。消费方向不建立无关的完整技术栈页；科技方向完整呈现技术路线与工程瓶颈；融合方向同时呈现消费逻辑、技术逻辑以及二者对产品价值和盈利的连接。统一使用“跟踪清单”作为后续事项页名。正文使用横向无内部边框长文本区；完成合同标记为数据密集的模块必须保留结构化明细表。正文数字在段落下方给出轻量数据依据，完整原始链接进入来源台账。生成器负责统一字号、色盘、实际使用区域、来源台账、模块可见位置和逐页渲染。项目专属图表通过叙事稿的 `visualizations` 提供底层数据和证据编号。
