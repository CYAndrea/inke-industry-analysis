# 研究执行合同

先读取 `references/output-profiles.md`。启动阶段必须先确认交付格式。用户未指定交付格式时，只询问“本次希望交付为飞书文档、Word、Excel 还是 PDF？”，暂停研究，不自行默认格式，也不追加已经可以由研究流程判断的市场问题。交付格式确认后，任务卡必须先确定资本市场阶段、研究对象类型、技术重要性、公司成熟度和信息完整度，再选择固定 `output_profile`。

## 任务卡选择

| 字段 | 要求 |
| --- | --- |
| `research_mode` | `industry_overview`、`public_company`、`private_company`、`competitive_scan` 四选一 |
| `decision_question` | 写成一项待决策问题，例如“该细分是否存在可投方向” |
| `must_cover_clusters` | 列出必须覆盖的竞争簇 |
| `required_sections` | 列出本次不可省略的章节 |
| `output_acceptance` | 列出成品的可检查条件 |
| `capital_market_stage` | `primary_market`、`secondary_market`、`not_applicable` |
| `research_archetype` | 大消费品、科技硬件、工业制造、软件平台、服务与医疗、其他 |
| `technology_materiality` | 非核心、支持性、核心护城河 |
| `company_maturity` | 早期验证、增长期、成熟未上市、拟上市、上市运营、不适用 |
| `information_availability` | 稀疏、部分、充分 |
| `output_profile` | 必须为 `references/output-profiles.md` 中的固定值 |
| `deliverable` | `飞书文档`、`Word`、`Excel`、`PDF` 四选一；用户未提供时启动阶段必须先询问 |

仅追问会改变上述字段的缺口；用户已给出的信息不得重复询问。

### 主体识别规则

| 输入信号 | 默认模式 |
| --- | --- |
| A 股、港股、美股或其他交易所上市主体 | `public_company` |
| 明确出现一级投资、融资、创始团队或项目筛选 | `private_company` |
| 只有行业名称，没有标的 | `industry_overview` |
| 明确要求竞品、可比项目或竞争地图 | `competitive_scan` |

用户未说明投资市场时，根据主体身份自动判断；用户未给标的时，不要求补充标的。任务卡需记录 `mode_rationale`，说明模式选择依据。

### 研究对象与技术重要性

任务卡另设两个独立字段，不能用“消费品／科技”互相替代：

| 字段 | 可选值 | 判断方式 |
| --- | --- | --- |
| `research_archetype` | `大消费品`、`科技硬件`、`工业制造`、`软件平台`、`服务与医疗`、`其他` | 按收入来源、购买决策和竞争方式判断 |
| `technology_materiality` | `非核心`、`支持性`、`核心护城河` | 判断技术是否直接决定产品性能、成本、交付、合规或估值 |

大消费品默认设为 `technology_materiality=非核心` 或 `支持性`。研究重点放在需求、品牌、产品、渠道、复购、价格体系、供应链和单位经济性；仅在技术改变产品体验、成本或合规时展开相关生产与配方。科技硬件、工业制造和软件平台若技术属于 `核心护城河`，必须把技术路线、工作机制、性能取舍、工程瓶颈、量产或部署状态及商业化影响写成完整段落。面向消费者的科技产品仍按技术重要性决定技术篇幅，不另设“混合型”类别。

### 有标的公司的输出决策顺序

当用户提供标的公司时，必须按照以下顺序建立任务卡，不能先套用行业模板：

1. **判断资本市场阶段**：上市公司归入二级市场研究；未上市且用户讨论融资、投资或项目筛选的公司归入一级市场研究；无法确认时先核验主体和上市状态。
2. **判断研究对象类型**：填写 `research_archetype`，例如大消费品、科技硬件、工业制造、软件平台或服务与医疗。
3. **判断技术重要性**：填写 `technology_materiality`。技术直接决定产品性能、成本、交付、合规或估值时，设为 `核心护城河`；技术只支持生产、质量或供应链时，设为 `支持性`；技术不构成主要竞争变量时，设为 `非核心`。
4. **生成输出配置**：根据资本市场阶段、研究对象类型和技术重要性组合决定研究章节、指标和核验动作；不得输出与组合无关的固定章节。

输出配置至少遵循以下规则：

| 组合 | 必须突出 | 应减少或省略 |
| --- | --- | --- |
| 一级＋大消费品＋非核心／支持性技术 | 产品、用户、品牌、渠道、复购、价格体系、供应链、融资与治理、可执行尽调 | 完整技术栈、上市公司式财务指标、难以取得的精细经营指标 |
| 一级＋科技硬件／工业制造＋核心护城河 | 技术路线、工程瓶颈、样机到量产、客户验证、成本曲线、供应链、融资与治理 | 没有证据支持的市场份额和伪精确经营指标 |
| 一级＋软件平台＋核心护城河 | 架构、训练或数据机制、部署与推理经济性、产品使用、客户验证、融资与治理 | 只描述功能名称而不解释系统门槛与商业影响 |
| 二级＋大消费品 | 品类结构、收入与利润、渠道、品牌、终端销售证据、估值与交易关注 | 与公司竞争无关的技术栈 |
| 二级＋科技硬件／工业制造＋核心护城河 | 技术路线、产品迭代、量产与良率、分部财务、资本开支、竞争、估值和跟踪 | 只描述技术名词而不解释商业影响 |
| 二级＋软件平台＋核心护城河 | 架构与部署能力、产品和客户、单位经济性、分部财务、竞争、估值和跟踪 | 将核心系统能力压缩为普通软件功能表 |

研究记录必须保存上述六个路由字段，质量验收时根据固定映射重新推导 `output_profile`，不接受只填写自由文本的组合描述。

## 研究模式合同

| 模式 | 必需内容 | 关键限制 |
| --- | --- | --- |
| `industry_overview` | 定义与分类、供需、技术或产品路线、产业链、竞争簇、市场口径、可关注方向与反证 | 不虚构标的投资要点；市场总盘、细分盘和平台监测分列 |
| `public_company` | 三至五条有标题的投资要点、业务与财务、竞争、估值或交易关注点、跟踪清单 | 精确财务以原始披露为准；不要以媒体转述替代年报数字 |
| `private_company` | 三至五条有标题的投资要点、产品、用户与付费、融资与股东、竞品、三至六项现实核验动作 | 不要求月度留存、库存天数、分区域利润或单厂成本，除非公司可提供或交易条款依赖 |
| `competitive_scan` | 用户购买旅程、竞争簇、可比项目、纳入与排除理由、竞争空白 | 只保留会影响投资判断的项目 |

### 阶段状态机

阶段必须按以下顺序推进：`intake → evidence → competition → editorial → delivery → quality`。`competitive_scan` 可从 `intake` 直接进入 `competition`；其他模式不得跳过 `evidence`。`editorial` 阶段先形成独立的读者版叙事稿，并运行叙事合同校验；不得一边组织观点一边创建工作表。每一阶段读取上一阶段产物，写入自己的固定文件。所有文件使用 `references/research-artifact-schema.json` 的字段，前置文件缺失或验收失败时返回修订清单。质量阶段运行跨产物对账器，未知证据编号、来源统计不一致、交付路径不一致或图表来源不完整均为阻断缺陷。

## 内容最低标准

当 `technology_materiality=核心护城河` 时，每个技术层级均需说明：主流路线、工作机制与产品适配、成本与性能取舍、量产或部署位置、工程瓶颈、投资意义。工程瓶颈必须使用完整句子解释“问题发生在哪里、为什么发生、会造成什么影响、行业如何解决或仍缺什么”，每层至少两句，禁止用逗号并列名词代替论述。若技术为非核心或支持性，只保留与产品、成本、质量和合规直接相关的技术说明，不强行制作完整技术栈。

技术层级固定字段为：`路线`、`产品适配`、`成本与性能取舍`、`量产位置`、`工程瓶颈`、`投资意义`。

无标的研究的需求端至少覆盖用户、购买场景、支付意愿与渠道；供给端至少覆盖关键投入、制造或交付、品牌或服务与渠道。竞争图必须包含品牌或直接产品、制造或供应链、平台或渠道等相关角色。

有标的研究的每条投资要点均需包含依据、失效条件与待验证信息。禁止将“领先”“显著”“较强”等表述作为无来源结论。

## 来源等级与停止规则

| 等级 | 使用范围 |
| --- | --- |
| A | 年报、招股书、交易所、政府、公司官网、产品页、投资方公告。用于财务、股权、产品参数、政策和精确数字。 |
| B | 中金点睛、智能涌现、Elsewhere 别处发生、虎嗅、投中网、投资界、可信行业数据库。用于一级项目、竞争动态和市场解释。 |
| C | 行业报告转述、平台榜单、聚合新闻。仅用于线索、趋势或明确标注的第三方测算。 |
| D | 营销软文、论坛、未经证实社媒。不得作为关键结论依据。 |

每个必覆盖竞争簇至少确认两家强相关项目。连续两轮检索没有新增强相关项目时停止该簇，并在竞争地图记录停止原因。

强相关项目至少满足目标用户、购买预算、使用场景、技术或供应链约束、渠道或转化机制中的两项。竞争地图必须包含 `searched_but_excluded`，记录被检索但未纳入的项目及理由。

## Excel 验收合同

无标的标准研究默认包含：`摘要与观点`、若干结论式正文页、`市场数据与来源`、`跟踪清单`。正文页名称直接表达章节判断，不固定使用“行业总览”“技术栈”“竞争格局”等分析标签。每张工作表首屏必须显示结论式标题和连续正文。

正文使用横向合并、无内部边框的宽文本区，按段落从上到下连续阅读。技术路线、工程瓶颈、竞争判断和投资观点先以正文呈现；参数、公司和时间序列确有横向比较需要时才使用数据表。数据表最多八列，超过则拆表。正文数字紧邻论证，段落下方设置轻量数据依据；完整网址在来源台账中可见。输出前渲染所有工作表，并记录叙事阅读与视觉检查结果。

`delivery-check.json` 固定包含：`schema_version`、`artifact_type`、`file_path`、`format`、`sheets`、`rendered_sheets`、`clipped_text`、`missing_links`、`formula_errors`、`visual_repairs`、`visualizations`、`passed`。每个图表记录工作表、证据编号、底层数据范围、来源链接、验收状态和限制条件。
