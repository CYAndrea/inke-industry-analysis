# 研究执行合同

先读取 `references/output-profiles.md`。用户已经指定聊天或 Excel 时选择对应路径；用户未指定时，只询问“本次希望以聊天格式还是 Excel 格式输出？”，暂停正式研究，收到选择后继续。不得根据请求长短、是否提到文件或团队习惯自行默认格式。两条路径都要完成三级路由；只有 Excel 路径必须建立并保存完整任务卡与阶段产物。

## 三级路由

### 第一级资本市场判断

第一级只在用户给出具体公司时触发。先识别准确法律主体、上市主体和品牌关系，再核验该主体是否已经在全球任一证券交易所挂牌交易。核验范围覆盖境内外交易所，不限于 A 股；双重上市或多地上市仍属于二级市场。

上市状态优先使用交易所官网、监管文件、公司投资者关系页面和最新定期报告。任务卡必须记录 `listing_status`、`listing_exchange` 与 `ticker`。品牌、子公司与上市母公司不得混为同一主体。仅处于 Pre-IPO、IPO 辅导备案、交易所申请受理、聆讯或招股阶段的公司，在证券尚未挂牌交易前仍按一级市场处理。

- 已上市公司：`research_subject=company`、`listing_status=listed`、`capital_market_stage=secondary_market`、`research_mode=public_company`。
- 未上市公司：`research_subject=company`、`listing_status=unlisted`、`capital_market_stage=primary_market`、`research_mode=private_company`。
- 仅给行业：`research_subject=industry`、`listing_status=not_applicable`、`capital_market_stage=not_applicable`、`research_mode=industry_overview`。

用户明确要求竞品扫描时，可将 `research_mode` 设为 `competitive_scan`，但不得改变主体、上市状态、行业方向和输出配置。

### 第二级行业方向与研究对象判断

先判断用户给出的是行业还是具体公司。只有行业时完成深度行业研究，路由在第二级结束。给出具体公司时，仍须研究公司所属行业，并继续进入第三级公司研究。报告中出现代表性公司或竞品不等于用户提供了标的公司。

消费方向满足以下主要特征：位于终端需求侧，个人或家庭是主要购买者，企业通过成品或服务直接获得消费者收入，竞争主要由需求、品牌、品类、渠道、价格、复购和用户体验决定。

科技方向满足以下主要特征：位于产业链上游或中游，企业、机构或政府是主要客户，销售对象多为材料、部件、设备、软件或技术服务，采购主要由性能、成本、良率、可靠性、部署、认证和工程验证决定。企业直接销售产品并不自动归入消费方向；销售给产业客户的产品仍按科技方向处理。

消费科技融合方向要求消费逻辑和科技逻辑同时具有实质影响。终端消费者的需求、品牌、渠道、价格和体验直接影响收入，同时技术路线、核心器件、工程能力、性能成本取舍和产品迭代直接影响购买决策、毛利或竞争壁垒时，填写 `hybrid`，并结合消费与科技两套模板。消费电子、智能汽车和面向消费者的智能硬件可进入该方向。

技术只承担后台运营、普通生产或营销支持时填写 `consumer`。产品面向消费场景，但主要收入来自企业客户且采购由性能、良率、可靠性、部署或认证决定时填写 `technology`。填写 `hybrid` 时，`orientation_rationale` 必须分别说明消费驱动、科技驱动以及二者如何共同影响收入、利润和竞争。

示例路由：

| 用户提问 | 识别结果 | 输出配置 |
| --- | --- | --- |
| 帮我研究一下锂电池行业 | 行业研究、科技方向，路由在第二级结束 | `industry_technology` |
| 帮我研究消费电子行业 | 行业研究、消费科技融合方向，结合两套行业模板 | `industry_hybrid` |
| 帮我研究贵州茅台 | 具体公司、二级市场、消费方向，进入第三级 | `secondary_consumer_company` |

### 第三级公司研究

第三级仅在 `research_subject=company` 时触发。具体公司研究必须包含所属行业分析，随后把研究重点放在公司。

一级市场公司共同覆盖三至五条有标题的投资要点、创始人与核心团队、估值、融资历程、主营业务或主要产品、业务与产品的具体分析及评价、竞争、主要风险和三至六项现实可得的尽调动作。估值必须注明日期、币种、轮次、来源和投前或投后口径；融资金额需标注累计融资、单轮融资、连续交割与重复统计风险。

一级消费公司进一步覆盖用户、使用场景、品牌、渠道、价格、复购、供应链和终端销售验证。一级科技公司进一步覆盖技术路线、工程瓶颈、知识产权、样机到量产或部署、客户验证、成本与性能、供应链和交付能力。

二级市场公司共同覆盖准确上市主体、交易所与证券代码、三至五条有标题的投资要点、主营业务和产品、管理层与股权、收入利润与现金流、分部结构、竞争、估值基准日、催化剂、风险和跟踪指标。二级消费公司进一步覆盖品牌、品类、渠道、终端销售、价格体系和盈利能力。二级科技公司进一步覆盖技术与产品路线、客户与订单、生产或部署、研发、资本开支、良率或交付效率及其对利润和估值的影响。

## 阶段状态机

聊天与 Excel 统一使用 `intake → industry_analysis → company_analysis || competition_analysis → synthesis → editorial → completion_audit → delivery → quality`。`||` 表示公司分析与竞争分析在行业门禁通过后并行执行。只有行业时，`company_analysis` 标记为不适用，其他阶段不得跳过。聊天路径使用内部交接包，Excel 路径保存 Schema v3 阶段产物。

| 阶段 | 主要任务 | 允许读取 | 必须形成 | 进入下一阶段的门禁 |
| --- | --- | --- | --- | --- |
| `intake` | 格式、三级路由、边界和决策问题 | 用户请求与必要主体核验 | 任务卡 | 格式、研究对象、行业方向、资本市场阶段和必需章节完整 |
| `industry_analysis` | 行业证据、市场与行业判断 | 任务卡、来源材料 | 来源台账与行业交接包 | 必需行业章节完成；关键结论均有证据编号；反向证据、边界和未决问题已记录 |
| `company_analysis` | 标的公司研究 | 任务卡、行业交接包、按编号调用的证据 | 公司交接包或不适用标记 | 公司任务完成主体、业务、经营和行业关联判断；行业任务明确不适用 |
| `competition_analysis` | 购买旅程与竞争格局 | 任务卡、行业交接包、按编号调用的证据 | 竞争地图 | 竞争簇达到停止规则；纳入与排除依据、反向证据和未决问题完整 |
| `synthesis` | 交叉验证、冲突处理与决策判断 | 任务卡、行业交接包、公司交接包、竞争地图、按编号调用的证据 | 综合判断交接包 | 决策问题已回答；冲突已处理；失效条件完整；章节蓝图包含页面、模块和证据归属 |
| `editorial` | 读者版叙事 | 综合判断交接包、必要证据台账 | 叙事稿 | 未引入综合阶段之外的新结论或新证据；页面与模块归属未改变；叙事与内容合同通过 |
| `completion_audit` | 按输出路径核对核心模块 | 全部阶段交接包、叙事稿、输出路径合同 | 模块完成审计 | 模块集合完全一致；规定要素、证据和必要表格齐备；阻断缺口为空 |
| `delivery` | 聊天或 Excel 制作 | 已通过门禁的叙事稿、模块完成审计与交付规范 | 最终回复或工作簿 | 内容不扩写；Excel 的全部模块具有唯一可见位置，并完成逐表渲染和链接检查 |
| `quality` | 跨阶段对账 | 全部阶段交接包和成品 | 研究记录 | 路由、证据、阶段依赖、文件路径和质量检查全部一致 |

每个交接包只保留：关键结论、证据编号、反向证据、判断边界、未决问题、已完成章节和下一阶段重点。禁止复制来源全文、完整检索过程和大段原始笔记。后续阶段优先读取任务卡与上一阶段交接包；只有核对关键事实时，才按证据编号读取来源台账。

阶段职责不得混用：检索阶段不写最终正文；行业阶段不提前形成公司投资结论；公司阶段不重复完整行业研究或制作竞品地图；竞争阶段不形成公司投资结论；综合阶段只允许针对关键冲突进行有限补证；叙事与交付阶段不得新增研究结论。完成度审计只判断内容是否齐备，质量验收只检查最终一致性与成品质量。任何阶段门禁失败时返回对应阶段补齐，不得在后续阶段代为修补。

## 内容最低标准

科技方向的行业与公司研究必须说明主流路线、工作机制与产品适配、成本与性能取舍、量产或部署位置、工程瓶颈和投资意义。工程瓶颈使用完整句子解释问题位置、形成原因、商业影响和当前解决状态，每个关键层级至少两句。消费方向仅保留与产品体验、成本、质量、供应链和合规直接相关的技术说明。融合方向同时完成消费需求、产品、品牌、渠道和价格分析，以及科技方向的技术栈与工程分析，并单独解释技术如何转化为消费者价值、定价能力、毛利和品牌差异。

技术层级固定字段为：`路线`、`产品适配`、`成本与性能取舍`、`量产位置`、`工程瓶颈`、`投资意义`。

无标的研究的需求端至少覆盖用户、购买场景、支付意愿与渠道；供给端至少覆盖关键投入、制造或交付、品牌或服务与渠道。竞争图必须包含品牌或直接产品、制造或供应链、平台或渠道等相关角色。

有标的研究的每条投资要点均需包含依据、失效条件与待验证信息。禁止将“领先”“显著”“较强”等表述作为无来源结论。

## 来源等级与停止规则

| 等级 | 使用范围 |
| --- | --- |
| A | 年报、招股书、交易所、政府、公司官网、产品页、投资方公告。用于财务、股权、产品参数、政策和精确数字。 |
| B | 中金点睛、智能涌现、Elsewhere 别处发生、虎嗅、投中网、投资界、可信行业数据库。用于一级项目、竞争动态和市场解释。 |
| C | 行业报告转述、平台榜单、聚合新闻。仅用于线索、趋势或明确标注的第三方测算。 |
| D | 营销软文、论坛、未经证实社媒。不得作为关键结论依据。 |

每个必覆盖竞争簇至少确认两家强相关项目。连续两轮检索没有新增强相关项目时结束该簇，并在竞争地图记录原因。

强相关项目至少满足目标用户、购买预算、使用场景、技术或供应链约束、渠道或转化机制中的两项。竞争地图必须包含 `searched_but_excluded`，记录被检索但未纳入的项目及理由。

## Excel 验收合同

无标的标准研究默认包含 `摘要与观点`、若干结论式正文页、当前输出路径的全部模块页、`市场数据与来源`、`跟踪清单`。正文页名称直接表达章节判断。每张工作表首屏必须显示结论式标题和连续正文。数据密集模块在模块页保留结构化明细表。

正文使用横向合并、无内部边框的宽文本区，按段落从上到下连续阅读。技术路线、工程瓶颈、竞争判断和投资观点先以正文呈现；参数、公司和时间序列确有横向比较需要时才使用数据表。数据表最多八列，超过则分为多张表。正文数字紧邻论证，段落下方设置轻量数据依据；完整网址在来源台账中可见。输出前渲染所有工作表，并记录叙事阅读与视觉检查结果。

`delivery-check.json` 固定包含 `schema_version`、`artifact_type`、`file_path`、`format`、`sheets`、`rendered_sheets`、`clipped_text`、`missing_links`、`formula_errors`、`visual_repairs`、`visualizations`、`module_locations`、`passed`。每个图表记录工作表、证据编号、底层数据范围、来源链接、验收状态和限制条件。每个核心模块记录唯一工作表、可见范围、内容类型和证据编号。
