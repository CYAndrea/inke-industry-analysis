# Excel 交付视觉系统

当用户选择 Excel 时，以可审阅的专业研究工作簿为目标，呈现清晰的视觉层级，同时维持信息密度、可编辑性和阅读效率。使用低饱和配色、合理列宽和长文本观点区，不将“投行风格”作为固定模板名称。

## 工作簿结构

完整公司研究固定合并为八个读者页面：

1. `摘要与投资判断`
2. `行业概览与市场阶段`
3. `用户产品与商业模式`
4. `渠道供应链与竞争格局`
5. `公司业务管理与治理`
6. `财务表现与盈利质量`
7. `估值催化剂与风险跟踪`
8. `来源与待核验事项`

只有行业时自动省略不适用的公司、财务和估值页面，最终工作表不得超过八张。页面数量不限制内容篇幅，各页允许按研究需要向下延伸。17 个或其他输出档案规定的核心模块继续在后台逐项完成审计，并根据 `assets/excel-reader-pages.json` 映射到上述页面。叙事稿的全部章节也必须映射到唯一读者页面，正文段落保持原文，不得再次概括。禁止生成“模块-”开头的逐模块工作表，也禁止建立额外的独立叙事页。将摘要页置于首位，展示中心论点和完整论证。正文页名称和标题直接表达读者需要理解的主题。长表使用冻结首行或首列、筛选器和可见的来源列。每张工作表关闭网格线，仅格式化实际使用区域。

## 色彩与层级

默认采用暖灰褐、灰豆沙、暖白和雾绿色的低饱和组合，形成克制、有留白感的研究资料风格。高饱和色仅用于极少数状态提示，不作为大面积标题底色：

| 层级 | 建议样式 |
| --- | --- |
| 工作表标题 | 暖灰褐 `#5B5257` 填充，白色粗体，18 至 20 磅，合并标题区，行高 38 至 44 |
| 一级章节 | 灰豆沙 `#C9B9B4` 填充，深灰褐粗体，12 至 13 磅，行高 24 至 28 |
| 二级章节 | 浅灰粉 `#EDE6E3` 填充，深灰褐粗体，11 磅 |
| 普通表头 | 暖灰褐填充，白色粗体，居中且自动换行 |
| 核心观点 | 暖白 `#FBFAF8` 底色，横向小标题与留白，使用较大的正文或单独观点卡片 |
| 已核验数据 | 浅绿色 `#E3F0E8` 填充或绿色状态标记 |
| 跟踪清单 | 浅杏色 `#FFF0D7` 填充，避免使用刺眼红色 |
| 来源链接 | 浅灰底色，蓝色下划线链接，字号可缩小一档 |

正文使用 Aptos 或微软雅黑，12 至 13 磅；来源和密集数据表不得低于 11 磅。数字右对齐并使用明确的数值格式，文字左对齐。不要混用超过两种字体，也不要为普通数据区填充深色。

## 版式规则

- 每张工作表从标题条、研究范围与更新时间开始，再进入数据或判断区。
- 使用合并单元格呈现标题和章节带，不在筛选、计算或数据录入区域合并单元格。
- 项目筛选表固定保留公司或项目、产品方向、阶段、初步判断、公开信息渠道和限制条件或待确认事项；项目名称使用深灰褐粗体，链接与判断分列。
- 以浅色细边框定义数据结构，在章节、总结区和观点卡片处使用较强边界。不要为每一个单元格设置粗边框。
- 通过有节制的留白、较高的标题行和合理列宽建立阅读节奏。长段文字优先拓宽说明列，再启用自动换行。
- 观点、技术解释和投资判断使用横向合并的无内部边框文本区。文本区应提供完整论证，不放进带筛选器的密集数据网格；以暖白底色、横向小标题、章节标题和留白形成层次。
- 每张正文页先放置完成中心论证所需的连续段落，再放置数据依据或必要比较表。每个完整章节至少两个相互衔接的段落，页面可容纳多个章节。段落按结论、形成机制、证据、投资含义和判断边界自然推进，不显示这些内部字段名称。
- 所有章节标题、观点标签和技术层级均横向排布。不得用侧边竖排色条承载标题或标签；需要强调时，在长文本区上方增加一行低饱和底色的小标题。
- 数据表只用于可比较数据和结构化项目卡。每一个数字在同一行提供完整的原始来源网址；正文引用的数字在段落下方单列“数据依据”，链接、口径和发布日期均完整可见。
- 当 `industry_orientation=technology` 或 `hybrid` 时，技术栈页按层级设置独立的长文本区。每层至少讲清主流路线、产品适配、成本和性能取舍、量产位置、工程瓶颈与投资意义；术语和部件名称仅能作为叙述的一部分。融合方向还需在同页或相邻正文页说明技术与用户体验、定价、毛利和品牌差异的联系。消费方向删除完整技术栈页，只保留与产品、成本、质量和合规直接相关的段落。
- 正文列宽以完整阅读为准。优先通过增加说明列宽、行高和自动换行保证长文本可读；技术工程瓶颈与投资意义应设置为宽列，超过八列时拆分工作表，不得把完整论述压缩成关键词。
- 每张工作表的首屏应呈现标题、当前章节和一段完整内容。调整列宽、行高与换行，使正文、表头、数字和网址无需点选单元格即可阅读；网址过长时换行显示，不能截断。
- 禁止将长段观点塞入七列以上的密集网格，禁止用技术名词清单代替路线分析，禁止使用高饱和大色块或竖排文字制造层级。
- 禁止把分析脚手架直接交付给读者。项目符号列表、标签卡片和多列表头不得承载主要论证；正文页不得以宽表作为首屏主体。
- 仅在能够强化比较时加入条形图、时间线、市场份额图或热力矩阵。图表使用同一色盘，避免默认配色和装饰性图形。
- 需要更新的数字、口径、公式或状态必须保留为可编辑单元格或公式，不能只写入图片或不可追溯的文本。

## 交付前核验

渲染检查每张工作表。确认读者能够沿工作表顺序从上到下理解完整论证，分析标签已经隐藏，正文段落之间存在承接关系，标题、长文本、来源链接、数字格式和图表均完整可见；修复截断、拥挤、空白区域过大、颜色失衡和文字层级不清的问题。对账 `narrative-draft.json` 的章节数量、`completion-audit.json` 的模块数量和交付记录中的唯一位置，任何正文章节或核心模块缺失时不得交付。将研究内容、来源和观点分别组织，确保阅读者能快速找到结论并回溯证据。
