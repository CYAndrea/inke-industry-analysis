# 质量门禁

## 阶段门禁

| 阶段 | 必须通过 | 失败时的处理 |
| --- | --- | --- |
| 启动 | 研究边界、标的、交付格式、核心判断完整 | 仅追问会改变结果的缺口 |
| 检索 | 来源台账字段完整；关键数字有地区、期间、单位与等级；竞品簇完成或满足停止规则 | 补检索，不以主观排序补足缺口 |
| 分析 | 事实、估算、推演与待核验内容可区分；核心判断有反证；技术层级满足六字段 | 重写结论，明确证据边界 |
| 叙事 | 中心论点、章节顺序和连续正文完整；分析脚手架不可见；表格均有必要性说明 | 返回叙事编辑阶段重写 |
| 交付 | 格式规范、链接、可读性、页面结构和来源台账完整 | 修复版式或链接后再交付 |
| 复盘 | 研究记录通过脚本；经验经用户确认 | 未确认经验只保留在项目记录 |

## 交付验收清单

- 核心判断回答了“为何成立、何时失效、还缺什么”。
- 成品形成连贯咨询叙事；章节标题表达判断，段落之间存在承接关系，分析标签和内部字段未进入读者版正文。
- Excel 正文页从上到下连续阅读，主要观点未被项目符号、标签卡片或宽表替代；数据表只用于必要的横向比较。
- 任务卡明确记录资本市场阶段、`research_archetype`、`technology_materiality`、公司成熟度、信息完整度和固定 `output_profile`；大消费品未被强行展开为完整技术栈，核心技术行业的工程瓶颈未被压缩为关键词。
- 公司研究以有标题的投资要点开场，未输出伪精确综合打分。
- 竞品比较包含类别与可比原因，覆盖了相关的非制造商角色。
- 每项市场数字说明地区、期间、单位和事实或预测属性。
- 一级项目仅保留现实可得的核验动作。
- 所有关键来源提供完整直达链接。
- 关键来源按 A、B、C、D 分级，来源等级与结论用途匹配。
- 竞品地图包含纳入项目、排除项目、检索簇和停止原因。
- Excel 已逐页渲染核验；飞书图表有口径与来源；Word/PDF 已完成布局检查。
- 技术栈表已通过列宽、行高或拆表保证完整论述可扫描；工程瓶颈每层至少包含问题、成因和商业影响。
- 语义内容已运行 `scripts/validate_content_contract.py`；来源统计与证据台账逐条一致；阶段产物路径真实存在且内容结构可读。
- 所有阶段产物使用 Schema v3；正文、投资要点、竞品、图表和研究结论的证据编号均能回连同一个证据台账。
- `delivery-check.json` 字段、工作表清单、渲染清单、可视化来源和最终文件路径已由跨产物对账器核验。

## 缺陷分级

| 等级 | 含义 | 处理 |
| --- | --- | --- |
| 阻断 | 标的错误、关键结论无来源、交付文件无法打开 | 不交付 |
| 重大 | 口径混用、错误资本市场身份、一级项目使用不现实指标 | 修复后交付 |
| 一般 | 个别链接缺失、表格截断、未标注待核验 | 修复或显著标注 |
| 轻微 | 不影响判断的措辞或版式瑕疵 | 集中修订 |

## 阻断条件

出现以下任一情况时不得交付：主体识别错误；关键结论无来源；市场边界混用；一级项目使用上市公司式经营指标；叙事稿缺失或未通过校验；分析脚手架在成品中大面积可见；正文主要依赖宽表或项目符号；阶段产物缺失；Schema 字段漂移；未知证据编号；来源统计不一致；交付文件无法打开；关键页面或链接不可读。
