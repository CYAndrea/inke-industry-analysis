# 输出配置与信息路由

## 任务卡字段

有标的或无标的研究均填写以下字段：

| 字段 | 可选值 |
| --- | --- |
| `capital_market_stage` | `primary_market`、`secondary_market`、`not_applicable` |
| `research_archetype` | `大消费品`、`科技硬件`、`工业制造`、`软件平台`、`服务与医疗`、`其他` |
| `technology_materiality` | `非核心`、`支持性`、`核心护城河` |
| `company_maturity` | `早期验证`、`增长期`、`成熟未上市`、`拟上市`、`上市运营`、`不适用` |
| `information_availability` | `稀疏`、`部分`、`充分` |
| `output_profile` | 见下表，不允许自由填写 |

## 输出配置

| `output_profile` | 适用条件 | 必须输出 | 控制范围 |
| --- | --- | --- | --- |
| `industry_consumer` | 无标的大消费品 | 概念、供需、品类、品牌、渠道、竞争、市场拆分、可关注方向 | 技术仅覆盖配方、生产、质量和供应链相关内容 |
| `industry_core_tech` | 无标的科技硬件、工业制造或核心技术行业 | 概念、技术栈、路线、工程瓶颈、产业链、供需、竞争和投资方向 | 每个技术层级完成完整论述 |
| `industry_consumer_core_tech` | 无标的消费场景且核心技术影响产品竞争力 | 概念、消费者价值、必要技术栈、工程瓶颈、产业链、供需、竞争和投资方向 | 技术层级只覆盖直接影响性能、成本或合规的部分 |
| `industry_software_service` | 无标的软件平台、服务或医疗行业 | 概念、用户与付费、供需、竞争、商业模式、监管约束、行业观点和跟踪清单 | 技术仅覆盖产品架构、交付能力或合规所需部分 |
| `industry_software_core_tech` | 无标的软件平台且核心技术决定性能、成本或商业化 | 概念、架构与数据机制、训练或部署系统、工程瓶颈、供需、竞争、商业模式和投资方向 | 每个核心系统层级解释机制、成本、瓶颈和商业影响 |
| `primary_consumer` | 一级＋大消费品 | 投资要点、产品、用户、品牌、渠道、复购、价格体系、供应链、融资、治理、三至六项尽调动作 | 不要求上市公司式精细财务指标 |
| `primary_core_tech` | 一级＋科技硬件或工业制造＋核心护城河 | 投资要点、技术路线、工程瓶颈、样机到量产、客户验证、成本曲线、供应链、融资和治理 | 不补造未披露的经营数字 |
| `primary_consumer_core_tech` | 一级＋消费产品且核心技术影响竞争力 | 投资要点、消费者价值、必要技术栈、工程瓶颈、产品验证、渠道与商业化、融资和治理 | 技术分析围绕消费者可感知价值与量产约束 |
| `primary_software_service` | 一级＋软件平台、服务或医疗 | 投资要点、用户与付费、产品使用、交付、留存或复购可得证据、合规、融资和尽调动作 | 只使用项目阶段能够取得的指标 |
| `primary_software_core_tech` | 一级＋软件平台＋核心护城河 | 投资要点、核心架构、训练或数据机制、部署与单位经济性、产品和客户验证、竞争、融资、治理与尽调动作 | 技术能力必须连接产品完成率、交付成本、收入质量和估值 |
| `secondary_consumer` | 二级＋大消费品 | 投资要点、品类与产品结构、收入利润、品牌、渠道、终端销售证据、竞争、估值和跟踪 | 不制作与判断无关的技术栈 |
| `secondary_core_tech` | 二级＋科技硬件或工业制造＋核心护城河 | 投资要点、技术路线、产品迭代、量产与良率、分部财务、资本开支、竞争、估值和跟踪 | 技术分析必须连接到利润、现金流和估值 |
| `secondary_consumer_core_tech` | 二级＋消费产品且核心技术影响竞争力 | 投资要点、财务与估值、消费者价值、必要技术栈、工程瓶颈、竞争格局、催化剂、风险和跟踪 | 技术分析服务于产品、成本和盈利兑现判断 |
| `secondary_software_service` | 二级＋软件平台、服务或医疗 | 投资要点、产品与客户、商业模式、收入质量、合规、竞争、估值和跟踪 | 指标以年报和监管披露为准 |
| `secondary_software_core_tech` | 二级＋软件平台＋核心护城河 | 投资要点、核心架构与部署能力、产品客户、单位经济性、分部财务、竞争、估值和跟踪 | 技术分析必须连接利润、现金流、资本开支和估值 |

## 信息来源路由

公司成熟度和信息完整度共同决定来源深度：

- `早期验证`＋`稀疏`：官网、产品页、创始人访谈、融资媒体、客户或渠道外部反馈。
- `增长期`＋`部分`：增加融资文件、招聘与组织线索、渠道和客户验证、行业数据库。
- `成熟未上市`或`拟上市`＋`充分`：增加审计财务、股权文件、监管辅导、客户集中度和正式尽调材料。
- `上市运营`：年报、公告、交易所文件、投资者交流和行业原始数据优先，媒体仅用于解释和线索。

公司自述与独立来源分开记录。来源等级表示权威性，`source_role` 表示来源角色，`independence` 表示是否独立验证，不能用一个等级同时表达三种属性。
